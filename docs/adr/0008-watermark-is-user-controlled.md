# 水印改由用户控制，推翻 design D3

Status: accepted

基座（变更 `add-image-workbench`，已归档）的 design D3 明确写着「水印用户侧不暴露开关：缺省取能力声明的默认值」，代码里的注释是 `# 水印用户侧不暴露开关（design D3）`。取向是：水印属合规项，应由管理员全局决定，不由终端用户逐次决定。

但实际状态与之矛盾：上游 API 的 `watermark` **默认值是 `true`**，而种子数据把 `watermark_default` 设成了 `false`。也就是说这套部署已经在把水印当**出图效果**在调，而不是当合规项在守。

**决定：推翻 D3。** 水印成为用户侧可见的开关；能力声明里的默认值作为用户看到时的初始值。管理员仍可通过默认值影响初值，但不再能阻止用户改。

理由：D3 的理由（合规）与这套部署的实际行为（效果）不一致，而两者无法同时成立。既然后者的证据在种子数据里、前者的证据只在注释里，按实际行为归一。而本次改动已经让所有出图参数都由能力声明驱动（ADR-0006），把水印单独留在管理员侧会造出一个无来由的特例——同一份清单管着所有参数，唯独水印不可见。

**后果**：水印不再能被管理员强制开启。若将来真出现「所有出图必须带水印」的合规要求，正确做法是给能力声明加一个「锁定」标记，让该模型的水印值不可被用户修改，而不是把开关整个收回管理员侧。

**Considered Options**

- 保留 D3：与 ADR-0006 冲突，且与实际行为不符——放弃。
- 现在就加「管理员可锁定水印」的开关：多一个配置项去覆盖另一个配置项，而没有当前的合规需求支撑——放弃（真需要时再加，见后果）。
