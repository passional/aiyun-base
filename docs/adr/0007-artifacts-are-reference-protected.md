# 产物可作为后续绘图任务的输入，因此受引用保护、几乎不可删

Status: accepted

图层拆分与交互编辑要形成「拆 → 改」闭环：图层拆分的产出中有若干图层，用户在画布上点选其中一个图层，把它改掉。这就要求**产物能再次作为绘图任务的输入**。

基座已有一处删除保护：绘图服务与绘图模型被绘图任务引用时拒绝删除，提示管理员改用停用（archived design D8）。但产物此前只是绘图任务的落盘结果——只有任务引用产物，没有产物被别的任务引用。一旦产物能作输入，产物就进入了被引用关系。

**决定：产物被其它绘图任务引用时拒绝删除，与 D8 的取向一致。** 不级联删除，也不留下指向已删产物的任务。

理由：与仓库既有的取舍一致，且另外两条路都会破坏「绘图任务可回看、可重试」这个基座承诺——级联删除会把用户的历史记录连带删掉；保留任务但标记「输入已失效」会让重试必然失败，而重试是基座已经提供的功能。

**后果（须记住）**：**产物几乎不可删。** 一次图层拆分产生一张底图加最多十六个图层，用户每改一轮就多出一批引用节点，历史只增不减。这是本次刻意接受的代价。若将来要放开，做法是给产物加引用计数并允许「先复制再引用」，或把产物生命周期绑到其来源绘图任务上随任务一起删——而不是把引用保护直接取消。

**Considered Options**

- 允许删除、级联删除引用它的绘图任务：用户删一个图层，连同用它做的编辑一起消失——放弃。
- 允许删除、保留任务但标记「输入已失效」：历史列表里出现无法重现的任务，且基座的「一键重试」在这种情况下必然失败——放弃。
- 产物不落库、只在上游 URL 有效期内可引用：上游 URL 二十四小时失效，闭环会在第二天断掉——放弃。
