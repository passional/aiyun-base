# 语音服务不复用「平台」或「绘图服务」，建为平级独立实体

Status: accepted

语音识别需要一处管理员可配的上游凭证与端点。系统里已有两个带凭证的配置实体——渠道评估的「平台」（`channel_eval_platform`）与绘图工作台的「绘图服务」（`image_workbench_service`）。直觉做法是复用其中之一。

**决定：不复用。** 新增与两者平级的独立实体「语音服务」，其下挂「语音识别模型」。语音服务只持有名称、调用凭证、状态与备注；语音识别模型持有上游模型标识、资源标识、完整端点 URL 与识别限额（文件大小、音频时长）。语音服务不引用平台，也不继承渠道、指定渠道、接入方式、能力声明或图片产物等概念。

理由：`平台` 的定义里绑着 new-api 管理接口的假设——管理员令牌、实时拉取渠道目录（ADR-0003）、渠道 pin（ADR-0001）；语音识别只需要一个凭证与一个 WebSocket 端点。`绘图服务` 面向图片生成（图片产物、能力声明、出图方式）；语音识别没有图片、没有出图方式，复用它会让模型表背上大量无关字段。两者都不能准确描述「一条只需 key、端点和识别限额的上游线路」。

**后果（须记住）**：同一火山账号若同时用于绘图与语音，key 会在绘图服务与语音服务各存一份；这与 ADR-0004 已接受的代价同源，是刻意取舍。首版只有语音识别（ASR），语音识别模型不区分类型；将来接入语音合成（TTS）时需要增加模型类型或新增实体并做迁移，不能假定现有模型字段可直接复用。

**Considered Options**

- 复用「平台」（加语音标记）：语音服务要背上管理员令牌、渠道拉取与 pin 等它用不到的字段；火山语音也不是 new-api 渠道——放弃。
- 复用「绘图服务」（加语音标记）：绘图服务的能力声明、出图方式与产物模型与语音无关，模型表会被迫容纳两套语义——放弃。
- 语音服务引用平台凭证：避免重复存 key，但把语音可用性绑死在评估平台的配置上——放弃。
