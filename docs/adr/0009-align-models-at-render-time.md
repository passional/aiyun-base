# 模型对齐在报告渲染时解析，不在运行创建时快照

Status: accepted

对比报告按**规范模型**分组，而渠道模型串 → 规范模型的归属关系在**报告渲染时**才解析（每次打开报告都查一遍别名表）；而不是在测试运行创建时就把规范模型 ID 快照进 `channel_eval_run_combo`。

理由：命名习惯差异是**事后才发现的**。运行创建时别名表往往还是空的——管理员要先看到「同一个模型落成了两行」，才知道需要补一条别名。若在创建时快照，补完别名后所有历史运行都要重算，而重算需要重跑或回填，实际上等于历史报告永远修不好。渲染时解析让「补一条别名 → 历史报告立刻正确」。

代价：Web 视图的呈现会随后续别名维护而变。这个代价被明确接受，因为——

1. 报告引用的是测量数据（样本），不是分组结论；分组只是**视图**，数据本身没变。
2. 导出件在内嵌 JSON 生成的那一刻冻结，归档不受后续别名维护影响（见 ADR-0002 的冻结原则）。

配套决定：自动归一化只产「疑似同族」**建议**，不自动生效；建议不落库，每次实时算。日期戳这类部分重合（`gpt-5.6-sol` vs `gpt-5.6-sol-20260115`）无法由规则判定，而**误并比漏配更危险**——漏配看得见（两行），误并会让报告给出一个基于混合样本、看起来正常的错误结论。因此归属关系必须有人签字。
