# ASR 音频在浏览器转码为 WAV，后端不引入 ffmpeg

Status: accepted

火山语音识别要求 16kHz 单声道 PCM16 WAV；后端镜像 `python:3.12-slim` 没有 ffmpeg，本地开发环境也不保证有。用户上传的音频可能来自 mp3、m4a、ogg 等格式。

**决定：转码放在浏览器。** 前端用 WebAudio 解码用户选择的音频，重采样为 16kHz 单声道，编码为 PCM16 WAV 后上传；后端只做 WAV 头、采样率、位深、声道数、大小与时长的校验，不承担格式转换。镜像不新增音频依赖。

理由：管理员工作台运行在现代浏览器中，WebAudio 能解码绝大多数常见音频格式；把转码放在上传前，后端与部署环境保持零音频依赖，也避免为大文件引入系统级工具链。转码只用浏览器内建能力，不引入前端第三方音频库。

**后果（须记住）**：浏览器无法解码的编码（个别 m4a/opus 变体）会在前端被拒绝，错误信息必须明确指出「浏览器无法解码该音频」，而不是静默失败；若将来需要支持服务端接收任意格式（例如开放 API 直接上传），必须重新评估引入 ffmpeg 或改用上游支持的其它格式，不能沿用本决定。

**Considered Options**

- 后端镜像安装 ffmpeg：后端可处理任意格式，但镜像体积与攻击面增大，本地开发也需额外安装——放弃。
- 原格式直传并声明 format：文档示例只展示 wav/raw，其它格式的支持范围与行为不明确，失败风险高——放弃。
- 仅允许用户上传 WAV：体验差，用户需要自行转换——放弃。
