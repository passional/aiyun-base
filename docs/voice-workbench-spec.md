# 语音工作台（ASR 首版）Spec

## Problem Statement

管理员需要在系统内直接使用火山引擎方舟 Agent Plan 的语音识别模型，但当前后台没有任何语音上游的配置入口，也没有上传音频转写的界面。调用凭证只能写死在环境变量或代码里，模型标识、资源标识与端点无法由管理员调整；用户要做语音转文字只能去外部控制台，转写结果也不会留在系统里，无法追溯或复用。

## Solution

新增「语音工作台」：管理员在后台登记语音服务（一条调用凭证）与语音识别模型（模型标识、资源标识、完整端点、文件大小与音频时长限额）；用户在语音工作台上传音频（支持一次最多 10 个文件，浏览器自动转码），得到带时间戳的转写文本，可复制全文、导出 `.txt`。每次转写形成一个转写任务，按用户留存历史，支持查看详情与删除。首版只做语音识别（ASR），不做语音合成。

## User Stories

1. 作为管理员，我想在后台登记一个语音服务并填写调用凭证，这样系统才能调用火山语音识别。
2. 作为管理员，我想在同一个语音服务下登记多个语音识别模型，这样我可以按需切换模型而不改代码。
3. 作为管理员，我想为每个语音识别模型配置上游模型标识，这样工作台提交的请求能命中正确的模型。
4. 作为管理员，我想为每个语音识别模型配置资源标识，这样上游鉴权头能正确标识所调用的服务。
5. 作为管理员，我想为每个语音识别模型配置完整的 WebSocket 端点，这样端点变更或走代理时不需要发版。
6. 作为管理员，我想为每个模型分别配置文件大小上限，这样我可以控制单次调用成本与上传体验。
7. 作为管理员，我想为每个模型分别配置音频时长上限，这样超长音频会在调用上游前被拒绝。
8. 作为管理员，我想在列表里只看到脱敏后的凭证（末 4 位）与「是否已配置」，这样明文 key 不会出现在页面上。
9. 作为管理员，我想在编辑服务时留空凭证表示沿用原值，这样我不必为了改名称而重新输入 key。
10. 作为管理员，我想在服务下还有模型时不能删除该服务，这样不会留下悬空的模型配置。
11. 作为管理员，我想在模型已被转写任务引用时不能删除该模型，这样历史记录不会失去归属。
12. 作为管理员，我想看到系统预置的「火山引擎语音」服务与「豆包流式语音识别 2.0」模型，这样我只需要填 key 就能开始使用。
13. 作为管理员，我想在没有主动连通性测试按钮的情况下，通过上传一段真实音频来验证配置是否可用，这样不会浪费额外的探测调用。
14. 作为工作台用户，我想看到当前可用的语音识别模型列表，这样我知道自己会使用哪个模型。
15. 作为工作台用户，当只有一个可用模型时，我想系统自动选中它，这样我少做一步选择。
16. 作为工作台用户，当没有可用模型或服务未配置 key 时，我想看到明确提示并知道去哪里完成配置，这样我不会面对一个无响应的上传框。
17. 作为工作台用户，我想点击选择或拖拽多个音频文件，这样我可以一次提交一批录音。
18. 作为工作台用户，我想一次最多选择 10 个文件并在超出时收到提示，这样我不会误选整个文件夹。
19. 作为工作台用户，我想让浏览器自动把 mp3、m4a、ogg 等音频转成上游要求的格式，这样我不需要事先手动转换。
20. 作为工作台用户，当浏览器无法解码某个音频时，我想看到针对该文件的明确错误，这样我知道问题出在文件编码而不是服务故障。
21. 作为工作台用户，我想在上传后逐个看到每个文件的状态（待处理、转码中、识别中、成功、失败），这样批量任务不会只显示一个整批转圈。
22. 作为工作台用户，我想让批量文件按顺序执行而不是并发，这样不会触发每用户串行限制或消耗过多额度。
23. 作为工作台用户，我想在某个文件失败时其它文件继续处理，这样单个坏文件不会毁掉整批。
24. 作为工作台用户，我想单独重试失败的文件，这样我不必重新上传整批。
25. 作为工作台用户，我想在识别成功后看到整段转写文本，这样我可以直接复制使用。
26. 作为工作台用户，我想看到带起止时间的转写分段，这样我可以定位到音频中的具体位置。
27. 作为工作台用户，我想一键复制全文，这样我可以粘贴到其它工具里。
28. 作为工作台用户，我想把转写结果导出为 `.txt`，这样我可以离线保存或交付。
29. 作为工作台用户，当文件超过大小或时长限额时，我想在上传前或识别前收到明确提示，这样我知道该压缩或裁剪到哪里。
30. 作为工作台用户，当我已经有一个识别请求在途时，我想在再次提交时看到「有正在进行的识别任务」，这样我不会误以为请求丢失。
31. 作为工作台用户，我想在历史列表里只看到自己的转写任务，这样我的文件名与转写内容不会被其他管理员看到。
32. 作为工作台用户，我想在历史列表里看到原文件名、大小、时长、模型、状态、耗时与创建时间，这样我可以快速找到某次转写。
33. 作为工作台用户，我想分页浏览历史，这样任务多时页面不会一次加载全部记录。
34. 作为工作台用户，我想打开某条历史查看完整的转写文本与分段，这样我可以回看旧结果。
35. 作为工作台用户，我想从历史详情里复制或导出结果，这样历史结果与刚完成的结果具备同样的可用性。
36. 作为工作台用户，我想删除单条历史，这样我可以清理不需要的记录。
37. 作为工作台用户，我想批量删除历史，这样我可以一次清理多条记录。
38. 作为工作台用户，我想系统不保存原始音频，这样我的音频内容不会长期留在服务器上。
39. 作为工作台用户，当上游返回错误时，我想在任务记录与界面上看到可读的失败原因，这样我知道是凭证、限额还是上游故障。
40. 作为工作台用户，我想在服务重启导致识别中断后看到任务被标记为失败，这样历史里不会永远停留在「识别中」。
41. 作为系统管理员，我想语音工作台与语音服务配置受独立权限控制，这样只有被授权的角色才能使用或修改配置。
42. 作为系统管理员，我想工作台与配置页以中文和英文显示，这样不同语言的用户都能使用。
43. 作为系统管理员，我想转写任务记录调用耗时与上游用量（若返回），这样我可以排查性能与成本问题。
44. 作为系统管理员，我想服务与模型支持停用而不删除，这样我可以临时关闭某条线路但保留历史与配置。

## Implementation Decisions

### 模块与分层

- 新增后端模块 `voice_workbench`，分为配置（服务与模型）与任务（转写）两个子模块，沿用现有业务模块的 controller / service / crud / model / schema 分层。
- 新增前端业务模块 `voice_workbench`，包含「语音工作台」与「语音服务配置」两个页面，使用现有 API 客户端、表格、弹窗与表单约定。
- 语音服务是独立上游实体，不复用「平台」或「绘图服务」（ADR-0010）。
- 首版只支持 ASR；服务与模型不设供应商或模型类型字段，将来接入 TTS 时通过迁移扩展（ADR-0010）。

### 配置模型

- 语音服务：名称（唯一）、调用凭证密文、状态、备注。
- 语音识别模型：所属服务、展示名、上游模型标识、资源标识、完整端点 URL、单文件大小上限、音频时长上限、状态、备注。
- 不设「接入方式」或「能力声明」；识别参数（ITN、标点、数字归一、分段）固定开启，不暴露给管理员或用户。
- 凭证沿用现有约定：创建/编辑接收明文，落库前加密；出参只回显掩码与是否已配置；编辑留空保留原值；操作日志自动脱敏。
- 服务被模型引用、模型被转写任务引用时拒绝删除，提示改为停用。
- 预置一条语音服务（凭证留空）与一个语音识别模型，默认值：模型标识 `bigmodel`、资源标识 `volc.seedasr.sauc.duration`、端点 `wss://openspeech.bytedance.com/api/v3/plan/sauc/bigmodel_async`、大小上限 20MB、时长上限 300 秒。
- 不提供主动连通性测试接口；配置是否可用由真实转写验证。

### 转写任务

- 转写采用同步接口：一个 multipart 请求包含一个音频文件与模型主键，请求期间完成上传、识别与结果返回。
- 批量由前端逐文件顺序调用同步接口实现，不引入异步任务队列；每个文件形成独立转写任务，成败互不影响。
- 同一用户同时只允许一个识别请求在途，用 Redis 占位实现，请求结束在 `finally` 释放；不同用户互不影响。
- 校验顺序：模型启用且服务启用且有凭证 → 文件大小 → WAV 格式（RIFF/WAVE、PCM、16kHz、16bit、单声道）→ 音频时长 → 调用上游。
- 原始音频不落盘；转写任务只记录原文件名、字节数、时长、服务与模型快照、转写文本、分段、状态、耗时、错误与上游用量。
- 转写任务按创建者隔离，列表与详情只能访问本人任务；支持单条与批量软删除。
- 服务重启时，遗留的「识别中」任务标记为失败，原因记为服务重启导致中断。

### 上游调用

- 使用现有 WebSocket 依赖实现官方二进制协议，不新增音频或语音 SDK。
- 握手头包含调用凭证、资源标识、请求 ID、连接 ID 与固定序号；全量请求为 JSON + gzip，音频分片为 gzip 二进制。
- 全量请求中的音频声明为 WAV / raw / 16kHz / 16bit / 单声道；用户标识取当前用户 ID；识别参数固定开启。
- 音频按固定大小切片，最后一片使用负序号与末片标志；分片不按实时节奏发送，而是尽快发完，保留一个可调的小间隔常量（ADR-0012）。
- 响应处理覆盖正常响应与错误响应，解析序号、事件、负载长度，gzip 解压后读取文本与分段，并在末包或错误时结束。
- 上游错误、连接错误与超时都写入任务记录并返回可读业务错误；不做自动重试，由用户手动重试。
- 不引入 ffmpeg；音频在浏览器转码为 16kHz 单声道 PCM16 WAV 后上传，后端只做格式校验（ADR-0011）。

### API 契约

- 服务：列表、下拉选项、详情、创建、编辑、删除。
- 模型：列表、下拉选项、创建、编辑、删除。
- 任务：转写（multipart）、列表（分页）、详情、删除（支持批量）。
- 权限点按「语音工作台:服务:查询/新增/编辑/删除」与「语音工作台:任务:查询/新增/删除」划分；配置写操作只授予管理员角色。
- 所有接口沿用统一响应包装、业务异常与操作日志；凭证字段命中敏感键脱敏规则。

### 前端

- 配置页采用「左服务、右模型」布局，与现有绘图服务配置页的交互一致。
- 工作台顶部选择模型；可用模型定义为服务启用、模型启用且凭证已配置。
- 文件选择支持点击与拖拽，一次最多 10 个；列表逐行展示状态与结果。
- 浏览器转码分两层：浏览器解码适配层 + 纯函数（重采样为 16kHz 单声道、编码 PCM16 WAV）；无法解码的文件直接标记失败，不发起请求。
- 批量顺序执行器与 UI 解耦，接收一个转写回调；失败行可单独重试。
- 结果区展示整段文本与分段（起止时间 + 文本），支持复制与导出 `.txt`；导出文件名取原始音频名。
- 历史列表分页、按用户隔离，详情展示文本与分段，支持单条与批量删除。
- 所有文案进入中英文语言包，使用现有 i18n 约定；页面遵循现有 UI 规范与设计令牌。

### 文档与领域语言

- 架构取舍记录在 ADR-0010（语音服务独立实体）、ADR-0011（浏览器转码）、ADR-0012（同步执行与网关超时）。
- 领域术语统一使用 `GLOSSARY.md` 的「语音识别」段：语音服务、语音识别模型、转写任务、转写文本、转写分段、批量转写、原始音频。

## Testing Decisions

- 测试只断言外部可观察行为：HTTP 状态与响应、落库后的任务状态与字段、协议字节与解析结果、纯函数输出；不断言私有方法、调用次数或内部数据结构。
- **S1 主缝合点（后端 HTTP API）**：配置 CRUD 与转写接口都通过 FastAPI 测试客户端验证，沿用现有业务模块的 SQLite 测试库与假鉴权夹具。转写接口在上游执行器边界注入假实现，覆盖：成功落库、上游错误标记失败、模型停用、服务无凭证、超大小、超时长、格式非法、串行锁冲突、用户隔离、批量删除。
- **S2 协议适配缝**：上游客户端接受一个假 WebSocket 传输对象（发送字节 + 异步迭代响应）。用固定二进制帧验证全量请求头、分片序号与末片标志、gzip、正常/错误响应解析与文本分段聚合。这是唯一需要感知帧格式的测试。
- **S3 WAV 校验纯函数**：直接测试 WAV 头解析与校验，覆盖非 WAV、错误采样率、错误位深、多声道、data 长度异常、超时长。
- **S4 前端音频管线纯函数**：用合成 `Float32Array` 测试重采样与 PCM16 WAV 编码，覆盖采样率、单声道下混、头长度与数据长度；浏览器解码适配层不单测。
- 批量队列按约定不做单元测试，由 `ts:check`、类型检查与手工验收覆盖。
- 先例：现有绘图工作台的配置 API 测试、任务 API 测试、上游客户端测试、能力声明纯函数测试，以及前端能力/选区纯函数测试；新测试沿用相同的夹具与断言风格。
- 迁移测试沿用现有 schema 漂移守卫：模型变更必须生成迁移，自动生成零差异。

## Out of Scope

- 语音合成（TTS）、语音对话、实时麦克风输入。
- 移动端（H5 / 小程序）适配。
- 异步任务队列、断点续传、跨设备任务恢复、并发批量转写。
- 服务端音频转码或引入 ffmpeg。
- 主动连通性探测或上游模型列表探测。
- 原始音频落盘、回听、重新识别。
- 跨用户可见的历史或共享任务。
- 除火山引擎方舟 Agent Plan 之外的语音供应商。
- 热词、说话人分离、情绪识别、语言选择等扩展识别参数。
- 对外开放的转写 API 或第三方调用凭证。

## Further Notes

- 已确认的风险：分片「尽快发送」是否被上游限速需要真实 key 验证；分片间隔做成常量便于调整。
- 5 分钟默认时长按部署网关 300 秒反推。调高限额前必须确认上游处理耗时与网关超时；若上游要求实时节奏，需改异步或调整网关，不能只改模型限额。
- 浏览器解码覆盖范围取决于浏览器实现；无法解码的文件在前端明确报错，后端不做兜底。
- 默认模型标识与资源标识来自官方文档与需求说明，均可在后台修改。
- 批量 10 个 5 分钟文件是顺序执行，总耗时可观；界面必须逐行显示进度。
- 本文档为本地 spec，未发布到 issue tracker；发布前需先完成 tracker 与标签配置。
