# image-workbench/service-config Specification

## Purpose
让管理员在后台自行登记图片生成的上游（绘图服务）与其下可用的模型（绘图模型），并为每个模型声明其真实能力，使工作台能按上游的实际接口形态与参数范围发起请求，而不把厂商差异硬编码进代码。

## Requirements

### Requirement: 绘图服务登记与凭证管理

系统 SHALL 提供绘图服务的创建、编辑、删除、列表与详情能力。绘图服务属性至少包括：名称、接入方式、base_url、调用凭证、启用状态、备注。调用凭证 MUST 加密存储，任何接口与页面 MUST NOT 回显明文凭证，仅可回显脱敏占位；编辑时留空表示沿用原凭证。绘图服务 MUST 是独立实体，MUST NOT 引用或复用渠道评估的「平台」，也 MUST NOT 继承渠道或指定渠道的概念。

#### Scenario: 创建绘图服务

- **WHEN** 管理员提交名称、接入方式、base_url 与调用凭证
- **THEN** 系统保存该绘图服务且凭证加密落库，列表与详情只显示脱敏后的凭证

#### Scenario: 明文凭证不被回显

- **WHEN** 管理员打开已有绘图服务的编辑表单或查看详情
- **THEN** 凭证明文不出现在接口响应中，表单以空值或脱敏占位呈现，提交时留空即保持不变

#### Scenario: 凭证泄露防护

- **WHEN** 系统记录绘图服务相关的操作日志
- **THEN** 日志中不出现凭证明文

### Requirement: 接入方式决定请求形态

系统 SHALL 为绘图服务提供"接入方式"这一属性，首期支持"火山方舟"与"OpenAI 兼容"两种取值。接入方式 MUST 影响的对外可观察差异为：参考图的上行形态——"火山方舟"把参考图作为与提示词同一请求体内的普通字段提交；"OpenAI 兼容"把参考图作为独立的多部分表单端点提交。接入方式 MUST NOT 由代码根据 base_url 或模型 ID 自动推断，MUST 由管理员显式选择。

#### Scenario: 火山方舟接入方式下的参考图

- **WHEN** 管理员为绘图服务选择"火山方舟"接入方式，用户以参考图发起生成
- **THEN** 请求发往与文生图相同的图片生成地址，参考图出现在同一请求体中

#### Scenario: OpenAI 兼容接入方式下的参考图

- **WHEN** 管理员为绘图服务选择"OpenAI 兼容"接入方式，用户以参考图发起生成
- **THEN** 请求发往图片编辑地址并以多部分表单提交参考图

### Requirement: base_url 填完整 API 前缀

绘图服务的 base_url MUST 填写为**完整的 API 前缀**，即已包含版本段（如 `/v1` 或 `/api/plan/v3`）。系统在发起请求时 MUST 只在其后追加资源路径，MUST NOT 自行推断或补全版本段。表单 MUST 给出明确的填写示例以区别于渠道评估「平台」的 base_url 语义。

#### Scenario: 火山方舟 Agent Plan 的 base_url

- **WHEN** 管理员填写 `https://ark.cn-beijing.volces.com/api/plan/v3`
- **THEN** 系统向 `https://ark.cn-beijing.volces.com/api/plan/v3/images/generations` 发起请求

#### Scenario: 多级路径前缀被原样保留

- **WHEN** 管理员填写的 base_url 含多级路径（如 `/api/plan/v3`）
- **THEN** 系统原样保留全部路径段，不截断也不重复追加

### Requirement: 连通性测试

系统 SHALL 提供绘图服务的连通性测试能力，用所填凭证与 base_url 向上游发起一次最小代价的真实请求以验证可用性，并返回明确的成功或失败原因。测试 MUST NOT 因失败而阻断绘图服务的保存。测试 MUST NOT 在工作台上产生可见的绘图任务。

#### Scenario: 凭证有效

- **WHEN** 管理员点击"测试连接"且凭证与 base_url 均有效
- **THEN** 系统返回成功，并显示上游返回的模型标识等可核对信息

#### Scenario: 凭证无效

- **WHEN** 管理员点击"测试连接"但凭证无效或 base_url 不可达
- **THEN** 系统返回明确失败原因，且不影响该绘图服务的保存

### Requirement: 绘图模型与两级结构

系统 SHALL 以两级结构组织配置：绘图服务持有凭证与 base_url，其下可挂多个绘图模型。绘图模型属性至少包括：模型标识、显示名称、能力声明、启用状态。模型标识 MUST 由管理员填写，系统 MUST NOT 在代码中硬编码模型标识，也 MUST NOT 依据模型标识的命名规则推断其能力——同一模型在不同入口下的写法并不相同。

#### Scenario: 一个服务挂多个模型

- **WHEN** 管理员在同一个绘图服务下依次添加两个绘图模型
- **THEN** 两个模型共用该服务的凭证与 base_url，列表中作为该服务的子项呈现

#### Scenario: 模型标识按原样提交

- **WHEN** 管理员填写的模型标识带有或不带有日期后缀
- **THEN** 系统把该字符串原样作为请求中的模型标识提交给上游，不做规范化改写

### Requirement: 绘图模型能力声明

系统 SHALL 为每个绘图模型保存能力声明，至少包含：可选尺寸取值、是否支持参考图及参考图张数上限、可选输出格式、水印默认值。能力声明 MUST 可编辑，MUST NOT 由代码内置的能力表按模型标识推断。工作台的生成表单 MUST 依据所选模型的能力声明收敛可选项：尺寸只呈现该模型声明支持的取值，参考图仅在声明支持时可用且数量受上限约束。

#### Scenario: 不同模型呈现不同尺寸选项

- **WHEN** 用户分别切换到两个可选尺寸取值不同的绘图模型
- **THEN** 尺寸选择器只呈现当前模型声明支持的取值

#### Scenario: 不支持参考图的模型不出现参考图入口

- **WHEN** 用户选择了一个能力声明为不支持参考图的绘图模型
- **THEN** 工作台不出现参考图上传入口；即使绕过前端提交参考图，后端也拒绝该请求

#### Scenario: 参考图数量超限被拒绝

- **WHEN** 用户为某模型上传的参考图数量超过其声明上限
- **THEN** 系统拒绝提交并提示该模型允许的上限

### Requirement: 能力声明的预置

系统 SHALL 在种子数据中预置火山方舟两个绘图模型（pro 与 lite）的能力声明作为默认值，使管理员无需查阅上游文档即可开始配置。预置内容 MUST NOT 包含任何调用凭证。预置的模型标识 MUST 仅作为占位提示，管理员填写值以实际为准。

#### Scenario: 全新库获得预置能力

- **WHEN** 全新库首次初始化完成，管理员打开绘图模型配置
- **THEN** 可看到火山方舟两个模型的能力声明已预置，尺寸取值分别为 pro 与 lite 各自实际支持的档位

#### Scenario: 预置不含凭证

- **WHEN** 检查种子数据
- **THEN** 其中不含任何调用凭证，绘图服务的凭证字段为空待管理员填写

### Requirement: 引用保护与停用

系统 SHALL 在绘图服务或绘图模型已被绘图任务引用时拒绝物理删除，并给出该对象存在历史数据的提示；管理员可通过停用使其不再可选。停用的绘图服务与其下模型 MUST NOT 出现在工作台的模型选择中，但历史绘图任务 MUST 仍可正常查看与下载。

#### Scenario: 删除被引用的绘图服务

- **WHEN** 管理员删除一个已产生绘图任务的绘图服务
- **THEN** 系统拒绝删除并提示该服务存在历史绘图任务

#### Scenario: 停用模型不影响历史记录

- **WHEN** 管理员停用一个已有历史绘图任务的绘图模型
- **THEN** 该模型不再出现在工作台的模型选择中，但引用它的历史绘图任务仍可查看与下载产物
