## Context

动机见 `proposal.md`。以下是约束本次技术选型的现状事实（均已核对代码）：

- **侧边栏的「仪表盘」节点不是后端菜单。** `backend/sql/sys_menu.json` 中不存在 dashboard/workplace/analysis 任何一行；该节点由前端静态路由经 `mergeShellRoutesIntoMenu` 注入。因此移除演示页面**不需要动后端种子**，但**只删路由定义不够**——注入逻辑会把 `/dashboard` 重新塞回菜单，并保留一个指向已删页面的重定向。
- **种子导入是整表级跳过。** `backend/app/__init__.py:31` 每次启动都执行 `init_db()`，但 `backend/app/scripts/initialize.py:174-186` 的判据是「表内是否有行」——有行则整表 `continue`，没有 upsert、没有值比对。结论有二：管理员在参数管理中的修改**不会被重新部署覆盖**；种子改动**只对全新数据库生效**，不影响既有库。菜单有专门的幂等合并（同文件 `:199-225`），参数没有。
- **参数管理 UI 覆盖全部 17 个种子键。** 字段列表在前端硬编码（`views/module_system/params/index.vue:300-325` 的 `rebuildFields()`），服务端枚举不驱动渲染。服务端禁止修改 `config_key`，只允许改 `config_value`。**没有「恢复默认」按钮**。
- **第三方 OAuth 四处渠道凭证全空。** 四个 provider 的 `ClientId`/`Secret` 默认均为空字符串，仓库内无任何 env / compose / DB / 管理页覆盖（`git log -S` 佐证从未填入真实凭证）。凭证缺失时后端降级为带错误参数的重定向而非 500，前端消费该参数并弹出错误提示——即「点击必然得到一条报错」。
- **首页存在两套数据来源并存的问题。** 一张 KPI 卡片走真实接口，其余统计来自 mock 模块；索引页仍以 `getDashboardMock()` 播种状态，旁边留有「后续替换为真实接口」的注释。真实接口的调用方在失败时使用空 `catch`，静默保留预设数值。
- **`mock` 模块同时承载一个被 API 层引用的健康项类型**，直接删除文件会断开该导入。

## Goals / Non-Goals

**Goals:**
- 让首页呈现的每个数值都能追溯到真实数据源，且失败时可见。
- 让管理台对终端用户可见的界面不再出现上游主体、上游外链与上游推广。
- 在移除演示页面与演示登录方式的同时，保住渠道评估既有功能与既有接口契约零改动。
- 保证清理后前端类型检查、lint 与测试全绿，且不因上游合并而产生长期摩擦。

**Non-Goals:**
- **不新增任何后端聚合端点。** 首页概览只用既有接口可零改动得到的指标（平台总数、运行总数、最近运行列表）。
- **不计算跨运行的成功率与平均延迟。** 该口径需要定义「成功率是否含异常样本、是否跨渠道聚合」，是一个独立的决策树，本次明确不做。
- **不改动渠道评估的任何数据流、接口契约与权限标识。**
- **不动 `frontend/docs/`、`frontend/app/`、README、包名与代码注释中的上游署名。**
- **不删除后端 OAuth 实现。**

## Decisions

### D1. 品牌类改动走参数管理，仅将备案号种子置空

品牌标识、系统名称、版本号、页脚各链接**不改种子、不改代码**，由管理员在参数管理维护；**唯一例外**是备案号种子值改为空字符串。

- **为什么**：已核实参数保存的值不会被重新部署覆盖，因此「能在系统里设的就不改代码」成立；而备案号不是品牌偏好，是主体资质——全新数据库若沿用上游作者的备案号，等同于把他人资质挂在自己的站点上。置空使新实例默认**不显示**备案号，这是安全的默认。
- **为什么不删掉该种子键**：参数管理字段列表按 key 硬编码，删键会让页面出现缺失字段；置空即可让该链接不渲染。
- **为什么不改其余种子值**：改了也只对新库生效，与管理员在界面上已设的值重复且可能冲突。

### D2. 用物理删除，不新造功能开关

移除项一律直接删除代码，不引入 `showXxx: false` 之类的新开关。**唯一例外**是复用 `config/setting.ts` 中**已存在**的开关（如通知、设置面板）。

- **为什么**：开关只是隐藏——被隐藏的项仍会在设置面板露脸、仍在 DOM 中、每次与上游合并都要重新理解一遍。且这批模块（演示卡片、推广通知、上游外链按钮）上游几乎不会改动，物理删除的合并冲突面很小。
- **为什么不删完再加开关**：本次的判据是「界面上不该存在」，不是「默认不显示」。

### D3. 演示页面整页删除，而非清空内容后保留路由

`/dashboard/workplace` 与 `/dashboard/analysis` 连同父级 `/dashboard` 节点、路由定义、菜单注入逻辑一并删除。

- **为什么**：`analysis` 的「内容」本身就是组件示例清单，抽掉演示数据后只剩空壳；`workplace` 是整套电商演示，清空等价于从零写一个新页面。两者都没有业务含义，保留只会占着菜单。
- **为什么连父节点一起删**：留着空的父节点仍会渲染为菜单项，且其重定向指向已删除的页面，会落进 404。

### D4. OAuth 只移除前端入口，完整保留后端能力

删除登录页的第三方登录入口区块；保留前端回调错误处理链路与后端全部实现。

- **为什么**：后端是一条「功能完整、只差凭证」的链路——凭证校验、授权地址组装、令牌交换、资料拉取、状态校验都已实现。删除数百行后端代码换来的收益只是少几处死入口，代价是将来要用需从零重写。而移除入口区块就已经彻底解决了「点击必然报错」这一实际问题。
- **为什么不删前端回调处理链路**：删掉会让「后端已配置错误参数并回跳」这条路径变成未处理状态——回跳参数被静默忽略，比留着更隐蔽、更难排查。
- **为什么现在移除入口**：四个渠道凭证全空，入口对用户只产生报错。按「呈现的入口必须与后端可用能力一致」的要求，未配置即不呈现。
- **恢复方式**：运维配置凭证后恢复呈现该区块，后端无需改动。

### D5. 首页概览只用既有接口，零后端改动

「平台数 / 运行数 / 最近运行」由两个既有接口得到，不新增端点。

- **为什么**：平台总数可由平台列表接口的全量查询直接得到；运行总数可由运行列表接口的分页总数得到，且该接口已支持按平台与状态筛选，足以支撑「按状态区分」的呈现。零后端改动意味着本次清理不引入新的契约与鉴权面。
- **代价**：最近运行的延迟指标需要逐次运行详情才能取得，本设计不取，首页概览只呈现状态类信息。
- **被否决的方案**：新增一个聚合端点。它会把「成功率如何定义」这一未决问题拖进本次改动，属于范围蔓延。

### D6. 健康项类型从 mock 模块迁移出去

删除 mock 模块时，先把其中的健康项类型移到 API 层类型定义处，再删文件。

- **为什么**：API 层引用了该类型。先迁移可避免删除文件时断开导入，也让「类型定义」不再寄居在即将消失的 mock 模块中。

### D7. 删除项与联动改动必须同批完成

以下四项是同一批不可分割的改动，任何一项单独提交都会留下破损状态：

1. 演示页面路由定义
2. 菜单注入逻辑（否则 `/dashboard` 会被重新塞回菜单）
3. 依赖「仪表盘子路由数 > 0」的既有测试断言（否则测试红）
4. 首页索引页对 mock 模块的引用与「待替换为真实接口」的注释

## Risks / Trade-offs

- **[既有测试断言失效]** → 期望「仪表盘节点仍有子路由」的用例必须在同批修改中调整；验收时以 `pnpm test` 全绿为准，而非仅看页面。
- **[删除 mock 模块断开 API 层导入]** → 先迁移健康项类型（D6），再删文件；以 `pnpm ts:check` 为准。
- **[菜单注入逻辑漏改导致演示入口复活]** → 路由删除与菜单注入删除、注入函数删除必须在同一任务内完成；验收时直接展开侧边栏确认。
- **[备案号种子置空后无法一键恢复]** → 参数管理没有「恢复默认」按钮，若管理员日后要填自己的备案号需手工输入。这是可接受的：置空是安全默认，回填是一次性动作。
- **[种子改动对既有库无效]** → 有意为之。既有库的备案号需管理员在参数管理改一次；本次不写迁移脚本，避免用一次性数据订正引入额外的部署风险。
- **[硬编码中文文案与 i18n 并存]** → 首页与登录页存在大量硬编码中文。本次顺带删除的文案不补 i18n 词条；保留项若涉及词条增删，需同时维护中英两份，否则会留下单语残留。
- **[移除页面属破坏性变更]** → 指向这两个页面的书签将落入 404。因为没有任何业务代码导航到它们，影响面仅限人工书签，接受。
- **[首页概览的权限面]** → 概览依赖渠道评估的查询权限；若当前登录角色无该权限，概览应整体不呈现而非报错。验收时以无权限角色登录确认。

## Migration Plan

**部署**：无数据库结构变更，**无 Alembic 迁移**。前后端各自构建部署即生效。

**种子改动的作用范围**：`keep_record` 置空只影响全新数据库。既有数据库不受影响；如需订正既有库的备案号，由管理员在参数管理界面改一次（不入本次代码改动）。

**回滚**：整体回滚走版本回退即可——本次不含数据迁移，无状态残留。若只想回滚备案号，需注意参数管理无恢复默认按钮，须手工重填。

**验收命令**：
- 前端：`cd frontend/web && pnpm ts:check && pnpm lint && pnpm test`
- 后端：`cd backend && uv run pytest`（本次后端仅改一个默认值与一处种子值，用于确认无回归）

## Open Questions

- 首页概览在无渠道评估查询权限时的呈现措辞（整体隐藏 vs 显示无权限提示）——不影响 specs、方案与任务拆分，实现时按现有权限组件惯例决定即可。
- 是否在后续变更中把「跨运行成功率与平均延迟」做进首页——需要先定义口径并新增聚合端点，属独立变更，本次明确排除。
