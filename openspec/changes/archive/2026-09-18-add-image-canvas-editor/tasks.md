## 6. 端到端验收（由用户执行，实现方协助）

**本节任务不由实现方自行跑完就算数。** 真实上游验收由用户执行；实现方负责准备可复现的步骤与记录模板、在用户执行时协助定位问题，并在用户给出结论后把结论回填进仓库（design.md、能力声明）。每条任务以**用户确认**为完成标准。

- [x] 6.1 对照真实上游核验三条上游假设（坐标标记语法、底图是否只剩背景、合成规则）（用户执行）：实现方准备可复现的请求并负责回填；验证：用户确认，且 design.md 的 Context 里每条上游事实都标注了「实测确认」或「仍为文档依据」
- [x] 6.2 「拆 → 改」闭环验收（用户执行）：完成「图层拆分 → 点选其中一层 → 改掉它」，确认新任务记录了来源、可反查，且该次拆分的**全部**产物在删除时被拒并指出引用者；实现方准备步骤并协助定位；验证：用户确认
- [x] 6.3 坐标不丢失验收（用户执行）：确认「提示词引用了选区但没有坐标」与「有选区但提示词没被引用」两种提交都被拒绝，且提示指出是哪一个选区；验证：用户确认
- [x] 6.4 重试验收（用户执行）：对一个含选区的失败任务执行一键重试，确认新任务带上了相同的选区与最终提示词，无需重新指定位置；验证：用户确认
- [x] 6.5 全量命令与构建验收（用户执行）：`cd backend && uv run pytest`；`cd frontend/web && pnpm ts:check && pnpm lint && pnpm test`；本地开发验证通过后，再按 `SKILL.md` 第 9 节重建并同步三份 dist 产物（`pnpm build:prod` + 带 `--delete` 的 rsync 到 `docker/nginx/web/dist` 与 `backend/dist`）；验证：用户确认命令全绿且三份 dist 已同步
