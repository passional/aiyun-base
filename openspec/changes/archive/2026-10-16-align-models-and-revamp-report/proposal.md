## Why

对比报告按**模型字符串全等**分组（`report/service.py:222-239` 用 `combo.model` 直接做 dict key），而模型串是各平台 new-api 渠道目录里原样暴露的（`platform/service.py:258` 逗号切分后原样快照）。不同渠道的命名习惯天然不同——同一个模型在 AIHUBMIX 叫 `claude-opus-5-5`、在 modelink 叫 `anthropic/claude-opus-5.5`，于是**同一个模型在报告里落成两行**，基准也对不上（`has_baseline=false`），横向对比直接失真。更糟的是这种失真**看不出来**：报告不提示"这两行本可以是一行"，也不提示"有多少模型没对齐"。

同时导出模板（`export_report.html.j2`，259 行、纯服务端静态渲染）信息架构比目标水准差一截：没有报告头与比较范围、没有逐模型可视化与指标切换、没有测试配置与执行信息、口径说明是写死的文本，且不可交互。

## What Changes

- **新增「模型映射」**：以**规范模型**（跨渠道对齐后的比较单元）为一等对象，渠道模型串经**模型别名**归属到它。别名 MUST 由管理员确认后才生效。
- **自动归一化只产建议，不自动生效**。系统扫描已观测到的渠道模型串，按渠道前缀、分隔符、大小写、日期戳四类依据给出「疑似同族」建议，并**显式标注依据**——日期戳这类"部分重合"必须由人拍板，自动合并错了报告结论就是错的。
- **报告按规范模型分组**。未对齐的模型**独立成行并标记**，绝不被隐藏或与其它模型合并；报告给出未对齐计数提醒。
- **映射留痕**：报告呈现组内各渠道**实际使用的模型串**，同一行内串不同时标注命名差异；口径说明**自动生成**并列出本次实际生效的映射关系。
- **新增可比性提醒**：比较所引用运行的运行参数，以事实陈述列出差异（热身、请求模板、每组合次数、异常阈值、请求间隔标为影响可比性；运行时间窗、模型数标为提示），不含评价性或建议性措辞。
- **新增测试配置与执行信息板块**：呈现所引用运行的参数快照与执行结果计数。热身目前只记录开关（`params_json.warmup` 为 bool，固定 1 次），MUST 按开关陈述，不得虚构次数。
- **导出 HTML 重写**为内嵌 JSON + 客户端渲染的自包含交互页，板块对齐目标信息架构：报告头、比较范围、关键指标概览、核心结论与可比性提醒、逐模型性能可视化（切指标、按系列筛选）、详细指标对比（可展开原始样本）、客户端实测与后台日志交叉对比、异常清单、测试配置与执行信息、自动结论与管理员备注、自动口径说明。仍然零外部依赖、离线可开、导出即冻结。
- **前端报告视图补齐**（KPI 行、未对齐提醒、命名差异、系列筛选），并提供**模型对齐确认入口**。

## Capabilities

### New Capabilities

- `channel-eval/model-mapping`：规范模型与模型别名的维护、自动建议的生成与确认、渠道模型串到规范模型的解析。

### Modified Capabilities

- `channel-eval/compare-report`：「跨渠道对比视图」改为按规范模型分组并补充未对齐呈现；「自动结论与管理员备注」补充可比性事实；「自包含 HTML 导出」补充导出内容清单与交互能力；新增「模型映射留痕」与「测试配置与执行信息」两条要求。

## Impact

**backend**：新增 `app/modules/channel_eval/model_map/`（controller/service/crud/model/schema）；`report/service.py` 分组逻辑改为经已确认别名解析规范模型；`report/schema.py` 视图契约扩展；`report/templates/export_report.html.j2` 重写。一次 Alembic 迁移（新增规范模型表与别名表，两张新表，不改动既有表）。

**frontend-web**：`views/channel_eval/report/components/ReportViewDialog.vue` 补 KPI 行与对齐呈现；新增 `views/channel_eval/model_map/` 页面（规范模型列表 + 建议确认）；`api/module_channel_eval/modelMap.ts` 新增；报告 api 类型同步；i18n 中英两份；菜单与 `channel_eval:model_map:*` 权限种子。

**frontend-app**：不涉及。

**docs**：`CONTEXT.md` 已含「渠道模型串」「规范模型」「模型别名」「模型映射」四个术语（本变更前已写入）；对齐时机与「建议不自动生效」的取舍见 `docs/adr/0009`。

**docker**：不涉及。

**兼容性**：`ReportModelGroupSchema.model` 的语义由「渠道模型串」变为「规范模型显示名」（未映射时为该串本身），字段类型不变；同时新增 `model_key`/`raw_models`/`alignment`/`family` 字段。别名表为空时，全部模型走「未对齐」路径，行为与现状一致（每个串各自成组），因此**存量数据无需回填**，历史报告不会因本次变更而改变分组结果。

**迁移**：两张新表，纯新增，无既有列变更；downgrade 丢弃两张表即可（映射关系丢失，报告退回全等分组）。
