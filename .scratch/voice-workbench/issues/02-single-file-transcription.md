# 02: 单文件语音转写（WAV 上传）

**What to build:** 用户打开「语音工作台 → 语音转写」，从可用模型中选择一个，上传一个 WAV 音频，得到转写文本与带起止时间的转写分段；可以复制全文、导出 `.txt`。超过模型限额、格式非法、上游报错时，界面与任务记录都给出可读原因。每次转写形成一个按用户隔离的转写任务；原始音频不落盘。同一用户同时只能有一个识别请求在途，重复提交会收到明确提示。服务重启后遗留的「识别中」任务被标记为失败。

**Blocked by:** 01: 语音服务与模型配置

**Status:** ready-for-agent

- [ ] 菜单出现「语音工作台 → 语音转写」，转写与查看受独立权限控制
- [ ] 模型下拉只列出服务启用、模型启用且服务已配置凭证的语音识别模型；只有一个时自动选中
- [ ] 没有可用模型时给出明确引导，指向语音服务配置，而不是静默禁用上传
- [ ] 单文件上传后依次完成校验：模型可用 → 文件大小 → WAV 格式（RIFF/WAVE、PCM、16kHz、16bit、单声道）→ 音频时长
- [ ] 校验失败不调用上游，任务记录为失败并保留原因
- [ ] 上游 WebSocket 客户端按官方协议发送握手头、JSON 全量请求、gzip 音频分片与末片标志，并解析正常/错误响应，聚合转写文本与分段
- [ ] 分片尽快发送，保留可调的小间隔常量，不按实时节奏发送
- [ ] 成功后任务记录保存文件名、大小、时长、服务与模型快照、转写文本、分段、耗时与上游用量（若有）
- [ ] 失败时任务记录保存可读错误；不自动重试
- [ ] 原始音频不落盘，任务记录不保存音频路径
- [ ] 同一用户重复提交时返回「有正在进行的识别任务」，不同用户互不影响
- [ ] 服务启动时把遗留的「识别中」任务标记为失败，原因记为服务重启导致中断
- [ ] 界面展示整段文本与分段（起止时间 + 文本），支持复制与导出 `.txt`，导出文件名取原音频名
- [ ] 转写 API 测试通过注入假上游执行器覆盖成功、上游错误、模型停用、服务无凭证、超大小、超时长、格式非法、串行锁冲突与用户隔离
- [ ] 协议测试用假 WebSocket 传输与固定二进制帧覆盖请求头、分片序号、末片标志、gzip 与响应解析
- [ ] WAV 校验纯函数测试覆盖非 WAV、错误采样率、错误位深、多声道、data 长度异常与超时长
- [ ] 页面文案支持中英文
