异常记录与注意事项

  • apiworld 上游结论（客户端 TTFT，越低越好）：
    · Claude 系：UCloud Claude_offical（opus 3.42s / fable 5.58s）≈ 京东云 Claude_B类（3.94s / 8.15s）<< Runapi Claude官方（13.05s / 18.44s）；
    · gpt-5.6-sol：UCloud GPT_offical（3.32s） 最快，其后 京东云 GPT_B类（4.42s）≈ aihubmix（4.68s）< Runapi GPT官转（4.96s）。
  • Runapi 渠道最差，建议避开：客户端 Claude 首Token 13–18s，后台日志同样确认（opus 11.4s / fable 16.4s，后台单次波动 1.9–22.2s）；gpt 走 Runapi 客户端也最慢。可正常返回，但体验接近不可用。
  • 后台侧各上游确认：UCloud Claude_offical 后台首Token opus 1.67s / fable 3.37s，为 Claude 上游最优；gpt 各上游后台首Token 1.80–2.53s 差异不大，客户端差异（3.32–4.96s）更多来自网络与时序。
  • 异常/冷启动 3 条（均为 claude-fable-5）：aihubmix 后台 10:39:28 73.6s；apiworld 后台 10:36:43 32.2s；apiworld 客户端首测 33.8s（复测回落至 5.7–12.2s）。
  • claude-fable-5 全渠道最慢（含 aihubmix 6.76s），fable 前置处理耗时明显，建议按需选用。
  • 「渠道后台日志汇总」中 apiworld 列为全部上游混合统计（Runapi 拉高均值），分上游明细见「apiworld 各上游·后台数据汇总」卡片。
  • TTFT 计的是「收到第一个 SSE chunk」的时间，Claude 系可能先返回 reasoning/元数据 chunk 再返回正文，故为首字节时延的近似值。
  • 模型 ID（gpt-5.6-sol / claude-opus-5 / claude-fable-5）为中转站自定义命名，两渠道 /v1/models 列表均可查。
